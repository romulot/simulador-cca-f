## Q1
Three of four newly onboarded engineers on a 200-person monorepo report that Claude Code never applies the team's commit-message convention, even though it has worked flawlessly on the tech lead's laptop for the past six months. Investigation shows the convention lives only in the tech lead's personal `~/.claude/CLAUDE.md`, and none of the other three engineers have that file on their machines. The tech lead wants every engineer who clones the repo to inherit the convention automatically, with no manual per-machine setup step required. What should the tech lead do?

- **A)** Ask each of the three newly onboarded engineers to copy the convention into their own `~/.claude/CLAUDE.md`, so every machine keeps its own personal copy of the rule.
- **B)** Move the convention into the project's `./CLAUDE.md` and commit it, so anyone who clones the repo loads the same convention automatically.
- **C)** Stand up an internal sync service that copies the tech lead's `~/.claude/CLAUDE.md` to every teammate's home directory on a nightly schedule.
- **D)** Keep the convention where it is, and have the tech lead re-paste it into the prompt at the start of every pairing session with a new engineer.

## Q2
Across all 40 repositories in a platform team's org, a managed policy at `/etc/claude-code/CLAUDE.md` bans direct commits to `main`, enforced identically by CI-triggered Claude Code jobs. This sprint, one engineer added a contradicting line to their project's `./CLAUDE.md` claiming push-to-`main` is fine for "hotfixes," and attempted it 12 times inside the CI job — every single attempt was still blocked. Why does the managed policy keep winning, and how do the two files actually combine in context?

- **A)** Memory layers concatenate into context instead of overriding each other, and the managed layer is non-overridable by design.
- **B)** The file that sits highest in the filesystem root always overrides every file loaded after it, so whichever layer is closest to root wins regardless of scope.
- **C)** User-level memory always wins over project-level memory because it loads last in the sequence and fully replaces earlier instructions.
- **D)** Adding `paths:` frontmatter to the project's `./CLAUDE.md` would let it take precedence over the managed policy for files in scope.

## Q3
In a monorepo containing 30 packages, `packages/api/CLAUDE.md` documents API-specific conventions for that package alone. Across a two-hour Claude Code session where the developer only edits files under `packages/web`, those API conventions never appear anywhere in context — but the instant Claude opens a single file inside `packages/api`, the conventions show up within that same turn. Is this the expected behavior, and why?

- **A)** No — subdirectory CLAUDE.md files are expected to load eagerly at session launch regardless of which files get touched, so this pattern is a bug worth filing.
- **B)** It only works because the root `./CLAUDE.md` contains an `@import` pointing at `packages/api/CLAUDE.md`; without that import it would never load.
- **C)** Yes — subdirectory CLAUDE.md files load on demand, only once Claude reads or edits a file inside that subtree, exactly as observed here.
- **D)** It only works because `packages/api/CLAUDE.md` is registered under `.claude/settings.json`; without that entry Claude would never discover the file.

## Q4
Through a chain of exactly 5 `@import` hops, a project's root `./CLAUDE.md` pulls in `@docs/style-guide.md`, which itself pulls in `@../shared/tone.md`, continuing three more hops deep. During a code-generation session, the 5th file in the chain never appears in context, even though the first 4 load correctly every time. The team then moves the entire repository to a new absolute path on a different machine, and the same 4-of-5 pattern persists unchanged. What explains this?

- **A)** `@import` paths resolve relative to the directory Claude was launched from, so relocating the whole repository to a new absolute path would have broken the chain.
- **B)** `@import` chains have no hop limit, so all 5 files should load without issue; the missing file is most likely a plain path typo.
- **C)** `@import` only accepts absolute paths from the filesystem root, so a relative reference like `@docs/style-guide.md` should never resolve in the first place.
- **D)** `@import` paths resolve relative to the importing file, and the chain is capped at 4 hops, so the 5th-hop file is never loaded.

## Q5
Across the last 6 pull requests in a CI-integrated Claude Code job, an engineer editing `services/api-gateway/handlers.py` keeps producing responses that violate a response-shape convention meant to be enforced automatically by `.claude/rules/api-conventions.md`, scoped with `paths: - "services/api/**"`. The file clearly lives in an API-related directory, and the rule has worked correctly for every other API file touched during that same window. What is the most likely fix?

- **A)** Copy the convention text directly into the system prompt for every session, so it applies regardless of which file happens to be open.
- **B)** Replace the rule file entirely with a `PostToolUse` hook that rewrites API responses to match the convention after Claude edits a file.
- **C)** Fix the `paths:` glob — e.g. `services/api-gateway/**` — since the rule silently never loads for this file because the current pattern doesn't match.
- **D)** Remove the `paths:` frontmatter entirely and just trust Claude to recall the convention from earlier in the conversation.

## Q6
A project's `./CLAUDE.md` has grown to roughly 900 lines covering build steps, API conventions, testing rules, and deploy checklists, all merged into one undivided file. Over the last three onboarding cycles, new engineers report skimming past most of the file, and contributors have noticed Claude repeatedly applying deploy-checklist language while editing unit tests that have nothing to do with deployment. What is the best fix?

- **A)** Split the content into focused `.claude/rules/*.md` files with `paths:` scoping, keeping `@import` from the root only for genuinely cross-cutting context.
- **B)** Keep everything in the single `./CLAUDE.md` — a 900-line monolith is the most deterministic way to guarantee every rule is always in context.
- **C)** Add a lightweight classifier step that inspects the current task and decides which section of the 900-line file is relevant before every turn.
- **D)** Move the entire 900 lines into the system prompt at the start of every session instead of keeping any of it in `CLAUDE.md`.
