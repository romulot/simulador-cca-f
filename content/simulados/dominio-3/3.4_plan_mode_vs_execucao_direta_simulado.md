# Simulado — 3.4 Plan mode vs direct execution (CCA-F, Domínio 3)

**Tópico:** plan mode × execução direta — modos de permissão (`default`/`manual`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`), formas de entrar em plan mode (`Shift+Tab`, `/plan`, `--permission-mode plan`, `permissions.defaultMode`), o que a aprovação do plano faz, Explore/Plan subagents, e onde plan mode **não** é garantia
**Exercício relacionado:** `exercicios/dominio-3/3.4_plan_mode_vs_execucao_direta.py`
**Formato:** múltipla escolha — 1 correta + 3 distratores (formato oficial da prova; questões em inglês)

6 questões. Uma única melhor resposta por questão.

> Responda antes de consultar o gabarito em `3.4_plan_mode_vs_execucao_direta_gabarito.md`.

## Q1
A developer productivity team tracks 214 Claude Code sessions per week. Sessions that start in plan mode average 3.1 turns before any file changes; sessions that start in `acceptEdits` average 1.4. A developer now has a `KeyError` in `parse_order`, with a stack trace pointing at line 88 and a payload that lacks the `discount` field. The fix is a single guard in one function. Which approach is most effective for this task?

- **A)** Run directly in `acceptEdits` mode, since the cause is already known and the change is scoped to one function.
- **B)** Enter plan mode with `Shift+Tab` so Claude can present the fix for review before editing.
- **C)** Delegate the fix to the Explore subagent so the investigation stays out of the main conversation.
- **D)** Set `permissions.defaultMode` to `plan` in `.claude/settings.json` so every session in the repository plans first.

## Q2
A team must migrate 47 modules from a callback-based HTTP client to an async one. Two approaches are on the table: a compatibility shim that preserves the old signatures, or rewriting every call site. A survey shows that 12 of the 47 modules pass the callback into third-party code, where the shim would silently change behavior. No file has been touched yet, and the team wants the approach settled before the first edit lands. Which approach is most effective for this task?

- **A)** Start in `acceptEdits` mode and let Claude migrate the modules one at a time, reviewing the combined diff at the end.
- **B)** Add a line to `./CLAUDE.md` asking Claude to always describe its approach before editing anything, then run the migration in `acceptEdits` as usual.
- **C)** Enter plan mode (`Shift+Tab` or `/plan`) so Claude explores the 47 modules read-only and proposes one approach to approve before any edit.
- **D)** Split the migration into sequential pull requests of three modules each, leaving the approach to whoever opens each PR.

## Q3
A team's `./CLAUDE.md` says "always present a plan before editing any file." Across 20 recent sessions, Claude edited files on the first turn in 14 of them and planned first in the other 6. The 14 all came from developers who launch Claude through a shared shell alias; the 6 came from developers who type `claude`. No `.claude/settings.json` in the repository sets `permissions.defaultMode`, and the status indicator in those 14 sessions read "accept edits on". What is the most likely root cause?

- **A)** Instruction-following degrades as a repository grows, so the `./CLAUDE.md` line is progressively ignored; moving those developers to a stronger model would restore it.
- **B)** The alias starts each session in `acceptEdits`, where edits are pre-approved — and the mode is set through these controls, not by an instruction written in `./CLAUDE.md`.
- **C)** A known regression in this Claude Code version makes plan mode silently inactive when it is requested from a memory file; pinning the previous version restores the behavior.
- **D)** The plan is in fact being produced but never rendered in the transcript; those sessions need `--verbose` for the plan to become visible before the edits.

## Q4
A CI job drives Claude Code with `-p` over a monorepo in three phases: locate every call site of a deprecated helper, propose a replacement, then patch. The discovery phase reads 60+ files and its raw output fills roughly 70% of the context window; by the patch phase, the run has auto-compacted twice, and 2 of the last 5 runs patched the wrong module. Spot checks confirm the discovered call sites themselves were correct. Which change most effectively addresses the cause?

- **A)** Let auto-compaction handle the transition between phases so the transcript shrinks before the patch phase.
- **B)** Set `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1` so Claude reads the files directly in the main context and saves an agent hop.
- **C)** Run the discovery phase three times and carry forward only the call sites that appear in at least two of the passes.
- **D)** Delegate discovery to the read-only Explore subagent, which runs in its own context window and returns only a summary.

## Q5
A platform team is onboarding 30 engineers to Claude Code on one repository. The policy is that no file may be modified until a human has approved Claude's plan, and the team accepts that this applies to every session, small fixes included. In a two-week pilot, 4 of the 30 engineers had edits land before any plan was shown; all four say they simply forgot. The instruction is already in `./CLAUDE.md`. Which approach is most effective?

- **A)** Rewrite the `./CLAUDE.md` instruction in stronger, more explicit language and re-share it with all 30 engineers at the next team meeting.
- **B)** Add `--plan-only` to the shared launch script, so no session can write to disk until its plan has been approved by a reviewer.
- **C)** Set `permissions.defaultMode` to `"plan"` in the repository's `.claude/settings.json`, so every session starts in plan mode by configuration.
- **D)** Keep the current setup and make diff review mandatory on every pull request, so no unreviewed change ever reaches the main branch.

## Q6
A CI pipeline runs Claude Code in a container where bypass permissions are available, so the job never blocks on a prompt. A new requirement states that the job must never modify anything under `migrations/`; 3 of the last 40 runs did. The team's fix so far was to launch the analysis step with `--permission-mode plan`, and one of those 3 runs happened after that change shipped. Which approach actually guarantees the requirement?

- **A)** Add deny rules — `permissions.deny: ["Edit(migrations/**)", "Write(migrations/**)"]` — or a `PreToolUse` hook that blocks those writes in any mode.
- **B)** Keep `--permission-mode plan` and also prefix every prompt with `/plan`, so plan mode stays active for the entire run.
- **C)** Run the step in `acceptEdits` and state in `./CLAUDE.md` that files under `migrations/` are off limits to any edit.
- **D)** Replace bypass permissions with `auto` mode, whose safety checks stop the commands it judges destructive.
