# Simulado — 5.4 Manage context effectively in large codebase exploration

Domínio 5 (Context Management & Reliability). 6 questões, formato oficial:
múltipla escolha, uma única melhor resposta.

## Q1
You are using Claude Code to explore an unfamiliar 4,000-file monorepo. After
roughly two hours and 60+ file reads in the same session, the answers change
character: instead of naming the classes it found earlier, the agent starts
describing "the typical pattern for a service like this," and in three of the
last five answers it cites no file at all. The earlier answers were specific
and correct. What is the most effective fix?

- **A)** Switch the agent to a model with a larger context window, so all the accumulated discovery output from the session fits without being lost.
- **B)** Have the agent keep a scratchpad file with each finding's file path and symbol, and reference it when asking follow-up questions.
- **C)** Run `/compact` as soon as the answers start getting vague, so the session recovers the detail that already slipped out of context.
- **D)** Add an instruction to `CLAUDE.md` telling the agent to always be specific and to cite the exact file path in every single answer it gives.

## Q2
A coordinator agent answers architecture questions about a large repository by
delegating searches. Currently the coordinator itself calls Grep and Read: a
single question such as "find all test files and their conventions" adds about
18,000 tokens of raw output to its context, and by the fourth question roughly
70% of the coordinator's context is discovery output rather than reasoning.
Answer quality drops as the session goes on. What is the most effective change?

- **A)** Spawn a subagent per question so it does the searching and returns only the findings, keeping raw output out of the coordinator's context.
- **B)** Truncate every tool result to its first 50 lines before it reaches the coordinator, regardless of which lines the question actually needs.
- **C)** Run `/compact` after each question so the discovery output already sitting in context gets summarized away before the next one starts.
- **D)** Raise the coordinator's `max_tokens` limit so its context window can hold more discovery output on every turn.

## Q3
Your exploration pipeline runs in three phases: map the layers, trace a
specific flow, then answer questions about it. Telemetry shows that 40% of the
tool calls in phase 2 repeat searches that phase 1 already performed, and the
phase 2 subagents frequently "discover" modules that phase 1 had already
catalogued. Each subagent prompt contains only the single question that
subagent was spawned to answer. What is the most likely root cause?

- **A)** The decomposition into three phases is too granular for this repository, so some overlap of work at the phase boundaries is expected.
- **B)** The coordinator's `allowedTools` configuration does not include `Task`, so the phase 2 agents fall back to searching on their own instead of being spawned.
- **C)** Phase 1's findings were compacted out of the coordinator's context before phase 2 even started its first investigation.
- **D)** Phase 1's findings were never summarized and injected into phase 2's prompts; subagents don't inherit the coordinator's context.

## Q4
A 40-minute exploration job walks a legacy repository with 22 separate
investigations, then produces a report. The job died during the third phase
when the machine slept. Rerunning it repeated all 22 investigations from
scratch, including the 15 that had already completed. The team wants reruns to
resume instead of restarting. What is the most effective approach?

- **A)** Rerun the job with `--resume <session-id>`, since resuming the session should carry the already-completed investigations forward automatically.
- **B)** Increase the job's timeout and wrap the whole run in a retry loop, so transient interruptions like a sleeping machine do not end it outright.
- **C)** Have each agent export findings to a known path, and write a manifest the coordinator loads on resume to inject the completed work into the remaining prompts.
- **D)** Use `fork_session` from the last known good session, so the exploration branches from that checkpoint instead of restarting from scratch.

## Q5
After adopting subagent delegation for every question in your codebase
exploration agent, median time per question tripled and 4 of the last 10
answers cited the wrong file. Reviewing the traces, many delegated questions
are narrow follow-ups — for example, "what does the function at line 88 of
`refund.py` do?" — about files the coordinator had already read minutes
earlier. The broad investigations still benefit from delegation. What is the
most effective adjustment?

- **A)** Delegate only investigations that are verbose or broad in scope, and answer narrow follow-ups directly when the file is already loaded.
- **B)** Pass the coordinator's entire transcript to every subagent, so each one starts with the same context the coordinator already built up.
- **C)** Raise the subagents' step limit so they can explore more thoroughly and gather more evidence before answering each question.
- **D)** Have every subagent write to a shared scratchpad, so findings accumulate across delegations regardless of question size.

## Q6
Your exploration agent writes to `findings.md` diligently — 127 entries after
three hours, each with a file path and a symbol. Answers still degrade over the
session: by hour three the agent is describing generic patterns instead of the
classes it recorded. Inspecting the session shows the agent has written to
`findings.md` 127 times and read it zero times. What is the most effective fix?

- **A)** Restructure `findings.md` with section headers and a summary at the top so the most important entries are easier to locate.
- **B)** Have the agent read the entries relevant to the current question back into context before answering it.
- **C)** Write the findings into `CLAUDE.md` instead, so they are loaded automatically at the start of every session.
- **D)** Reduce how often the agent writes to the scratchpad so that only high-signal findings are recorded.
