# Simulado — Task Statement 5.6: Preserve information provenance and handle uncertainty in multi-source synthesis

> Domínio 5 · 6 questões · escolha a **única melhor** resposta.

## Q1
A multi-agent research system runs eight subtopics per brief, one subagent each, and a synthesis agent merges the eight reports into one document. Each subagent currently returns a two-paragraph prose summary of what it found. Across 60 briefs an audit sampled 240 claims from the final documents and could trace only 96 of them back to a specific source document; the other 144 named an institution, a year, or nothing at all. Every source was credible and no subagent failed. Which change most effectively restores traceability?

- **A)** Instruct the synthesis agent, in its system prompt, to cite the source document for every claim it writes into the final report.
- **B)** Have each subagent return claims as structured records with `fonte_id`, the supporting excerpt and `data_publicacao`, and have synthesis carry those fields through.
- **C)** Give the pipeline a larger context window, so that subagent findings never have to be compressed into prose summaries before the synthesis step runs.
- **D)** Normalize the eight subagent outputs into one uniform bullet format before synthesis, so that the merge step handles every finding in exactly the same way.

## Q2
A structured-extraction pipeline pulls headline metrics out of published reports. For annual instant-payment transaction volume, two extractions from the same institution disagree: 42.8 billion and 63.1 billion. Both were extracted correctly from their documents, and the reference periods are 2023 and 2024 respectively. Across 500 metrics, 34 pairs look like this, and the pipeline forwards each pair to a reviewer as a "value conflict". Reviewers close 31 of the 34 as "not a conflict" without changing anything. What is the most effective fix?

- **A)** Always forward the more recent of the two values, since a newer publication from the same institution supersedes the older one for that metric.
- **B)** Rank the publishing institutions by credibility and forward the value from the higher-ranked one, escalating only when two publishers are ranked equal.
- **C)** Require every extracted value to carry `periodo_referencia` and `data_publicacao`, and report values for one metric as a dated series.
- **D)** Keep forwarding both values, annotating each with the document it came from, so the reviewer can see which publication each number belongs to.

## Q3
A multi-agent research system synthesizes findings from twelve sources per brief. To control noise, the synthesis step reports only claims that at least two sources confirm and drops anything a single source states. Over 40 briefs, readers report that the documents read as unanimous. An audit of one brief shows that the three topics where sources genuinely disagreed — same reference period, same definition, different numbers — produced no output at all, while the topic where three sources stated an identical figure was reported. No source was unreliable and no subagent failed. What is the most likely root cause?

- **A)** The two-source rule removes exactly the disputed claims: when sources disagree, no two state the same number, so a contested finding never clears the bar.
- **B)** The synthesis prompt carries no instruction to mention disagreement between sources, so the agent writes only the points that were straightforward to state.
- **C)** Twelve sources per brief is too coarse: with the topics decomposed further and more subagents per topic, a second confirmation for each disputed number would appear.
- **D)** Source quality is uneven across the twelve sources, so a credibility model should score each source before the confirmation rule is applied to its claims.

## Q4
A customer-support resolution agent delegates account lookups to a billing subagent whose report tool takes `{"valor": number, "unidade": string, "fonte": string}`, all three `required`, with `strict: true`. Over 900 cases, 210 accounts carried two applicable figures held in different systems — a posted balance and a pending balance. In all 210 the subagent reported one figure and never mentioned the other, the resolution agent quoted it to the customer, and 47 of those cases were reopened. The subagent's prompt tells it not to reconcile. What is the most likely root cause?

- **A)** The subagent is ignoring its instruction not to reconcile; the prompt needs an explicit rule and a few-shot example showing two figures reported side by side.
- **B)** The report contract holds a single `required` value, so it cannot express two figures — the subagent is filling the only field the schema gives it.
- **C)** The subagent's `max_tokens` is too low to fit two figures, so the second one is truncated before the report tool call is completed.
- **D)** Reconciling is acceptable when it is transparent: the subagent should keep choosing one figure and add a free-text note explaining why it chose that one.

## Q5
A research brief covers fraud rate per million transactions for the first half of 2025. Two of its twelve sources state 4.6: a consultancy bulletin, and a news report published three weeks later. The excerpt from the news report attributes the figure to that same bulletin and adds no measurement of its own. A third source, a supervisory authority, states 3.1 for the same period under the same definition. The pipeline marks any figure that two sources state as well-established, and reported 4.6 that way in 9 of 40 briefs. What should the report do here?

- **A)** Keep the current rule: two credible sources state 4.6 and only one states 3.1, so 4.6 is the well-established figure and 3.1 is the outlier to note.
- **B)** Drop the news report, which adds no measurement of its own, and report the consultancy's 4.6 as the figure from the more credible remaining source.
- **C)** Mark the topic as contested and route it to a human reviewer, since a figure restated by a second source cannot be verified automatically.
- **D)** Record that the news report restates the bulletin, so the topic holds two independent measurements — 4.6 and 3.1 — reported with each source's method and period.

## Q6
An extraction pipeline reads regulatory filings. In one filing the batch-size limit appears twice: the summary table states 500 and a footnote in the same document states 250, with nothing explaining the difference. Across 1,200 filings this pattern occurs 18 times, always inside a single document, from a single publisher, on a single publication date. The pipeline applies its standard multi-source rule — record both values with source attribution and continue — and downstream consumers have shipped the wrong limit twice. What is the most effective handling?

- **A)** Route these 18 filings to a human reviewer: both figures come from one document, one publisher and one date, so no provenance field can separate them.
- **B)** Keep recording both values attributed to the same document and let each downstream consumer decide which of the two applies to its own use case.
- **C)** Take the figure from whichever part of the filing was revised most recently, since a later statement inside a document supersedes an earlier one.
- **D)** Run the extraction twice with different prompts and record only the figure that both passes agree on, dropping any figure that appears in a single pass.
