# Simulado — Task Statement 5.1: Manage conversation context to preserve critical information across long interactions

> Domínio 5 · 6 questões · escolha a **única melhor** resposta.

## Q1
A customer-support resolution agent handles conversations that routinely run past 40 turns, and its harness folds everything older than the last eight turns into a running summary. Over one quarter, 18% of resolved cases had to be reopened: in each of them the agent's closing offer contradicted something already agreed — a different refund amount, a deadline that had been promised. The reopened transcripts show the same shape in the summary — "the customer asked about a refund and was unhappy with the wait" — with no figure, no date, and nothing about what the customer said they expected. Which change is most effective?

- **A)** Instruct the summarizer to be more thorough, listing every commitment it folds in so that nothing material is dropped.
- **B)** Adopt a model whose context window is far larger, so the conversation does not have to be folded.
- **C)** Move amounts, dates and the customer's stated expectation into a case facts block, re-sent in every prompt so they bypass the summary.
- **D)** Score the customer's sentiment on each turn and keep verbatim only the turns scored negative, since those are the turns where commitments get made.

## Q2
A structured-data-extraction pipeline runs in two stages. The reading agent opens each source document and returns a 900-word prose narrative of what it found; the synthesis agent then receives twelve narratives and must emit one record per document carrying the reported figure, its unit, the reporting period and the source. Across 40 batches, synthesis left the figure null for 6 of every 12 documents and attributed two figures to the wrong document. Hand-checked, the narratives contain every figure correctly, and a spot check that fed one narrative per request still left the figure null in 4 of 12. Which change is most effective?

- **A)** Have the reading agent return structured records — each fact with its source citation and a relevance flag — instead of prose.
- **B)** Rewrite the synthesis prompt to be more economical, telling it to prioritize figures, units and sources over narrative detail.
- **C)** Split the synthesis input into four chunks of three narratives, synthesize each chunk on its own and concatenate the partial results.
- **D)** Move the synthesis stage to the Message Batches API, so the twelve narratives are processed asynchronously inside its 24-hour window.

## Q3
Each subagent in a multi-agent research system calls a company-data tool whose result carries 44 fields per record, of which the research brief needs five: legal name, headcount, filing date, revenue and the filing's source URL. A subagent typically makes nine such calls before writing its section. Instrumentation shows tool results occupying 71% of the subagent's context by the ninth call, and sections written after call six omit facts the subagent itself had established at call two. Which change is most effective?

- **A)** Apply one fixed whitelist — the five fields most frequently requested last quarter — discarding the rest at the tool boundary.
- **B)** Fold the accumulated history into a running summary once it crosses a size threshold, and go on appending tool results.
- **C)** Give the subagent a more capable model, which can hold more facts in play before the earlier ones start dropping out.
- **D)** Trim each tool result to the fields the current brief calls for, so the rest does not enter the history.

## Q4
A developer works several open issues inside one Claude Code session, pasting each issue's constraints as they come up. Reviewing 11 such sessions, the team found 3 in which the patch for one issue silently honoured a constraint belonging to another — in one case keeping a legacy adapter that only issue #398 required, in a session whose current task was issue #412. Every constraint had been stated correctly at the time it came up. Which structure is most effective?

- **A)** Maintain one facts block that concatenates the constraints of every issue open in the session.
- **B)** Give each issue its own context layer, plus a one-line index of the other open issues alongside it.
- **C)** Require reporters to split multi-topic reports, filing one separate issue per topic in the tracker.
- **D)** Add a step that classifies each new message to detect when the developer has switched issues, then loads that issue's constraints.

## Q5
The support agent carries a validated case facts block — order value, dates, entitlement tier, prior credits and the resolution the customer said they expect — re-sent verbatim in every request. Escalated conversations run past 60 turns, so the harness now drops the oldest turns outright once the transcript passes turn 40, keeping request size flat. Last month 7 escalations re-asked the customer for a diagnostic result already reported at turn 9, and two repeated a workaround the customer had already rejected. Which is the best change?

- **A)** Summarize the narrative in the turns before the cutoff, keeping the case facts block verbatim so its values still travel intact.
- **B)** Revert to re-sending the whole transcript verbatim on every turn, since the complete history has to travel with each subsequent request.
- **C)** Raise the cutoff and adopt a larger context window, so longer transcripts keep fitting as conversations grow.
- **D)** Keep the cutoff where it is and trim the case facts block down to the two or three fields most recently referenced.

## Q6
A research coordinator concatenates nine subagent reports into a single 14,000-word input and writes the client brief from it. An audit of 30 briefs found that findings from reports 1–2 and 8–9 reach the brief 94% of the time, while findings from reports 4–6 reach it 31% of the time. Spot checks confirm the middle reports are no weaker than the others, and the aggregated input uses well under half of the available context window. Which is the best change?

- **A)** Move the coordinator to a model with a much larger context window and re-run the aggregation there.
- **B)** Aggregate three separate times and keep a finding only when two or more of those aggregations surface it.
- **C)** Open the input with a summary of every report's findings, and mark each report with an explicit section header.
- **D)** Re-run the subagents whose reports land in the middle of the aggregation, so their findings are produced a second time.
