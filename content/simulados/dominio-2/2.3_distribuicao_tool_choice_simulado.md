## Q1
In a six-agent research pipeline (Scenario 3), production telemetry shows that the subagent granted all 18 system tools "for convenience" misselects the wrong tool in 22% of its turns, compared with a 3% misselection rate for subagents scoped to only the tools their role needs. The team wants a fix that reliably improves selection accuracy without retraining or replacing the model. Which change is the single best fix?

- **A)** Set `tool_choice` to `"any"` so the model is forced to choose among all 18 tools on every turn.
- **B)** Scope the subagent down to roughly the 4-5 tools its role actually needs, adding only a couple of high-frequency cross-role tools if truly necessary.
- **C)** Route every request through a lightweight classifier that first predicts a candidate tool name from the 18 before the model is invoked.
- **D)** Reorder the 18 tool definitions in the system prompt so the most frequently used ones are listed first.

## Q2
In a CI code-review pipeline (Scenario 4), the team has three tools available — `run_tests`, `run_linter`, and `post_review_comment` — and requires that every pipeline run open with a call to `run_linter` before anything else happens, while every subsequent tool call in that same run should remain freely selectable based on the model's judgment. Which `tool_choice` configuration satisfies both requirements?

- **A)** Force `tool_choice` to `{"type":"tool","name":"run_linter"}` for the first turn of the run only, then switch back to `"auto"` for every turn after that.
- **B)** Force `tool_choice` to `{"type":"tool","name":"run_linter"}` on every single turn of the run, not only the first.
- **C)** Set `tool_choice` to `"any"` for the whole run so a tool call is guaranteed on every turn.
- **D)** Add "always call run_linter first" to the system prompt and leave `tool_choice` at its default `"auto"` value.

## Q3
In a customer-support pipeline (Scenario 1), a support agent has two closely named tools, `resolve_ticket` and `close_ticket`, and telemetry shows a 14% rate of calls to the wrong one of the pair. Hoping to fix this, the team sets `tool_choice` to `{"type": "any"}`. Three weeks after the change, the agent never again replies with plain conversational text, but the 14% cross-selection rate between the two tools is exactly unchanged. What does this outcome best reveal, and what should the team do next?

- **A)** `"any"` evaluates each tool's description more carefully than `"auto"` does before selecting, so it should already have resolved the overlap between `resolve_ticket` and `close_ticket`; the request was likely misconfigured somewhere else.
- **B)** `"any"` only forces a tool call instead of a text reply; it does not decide which tool is correct among overlapping ones. The real fix is sharpening the two tools' descriptions (2.1), not `tool_choice`.
- **C)** Fine-tune a small classifier to disambiguate between `resolve_ticket` and `close_ticket` before the main model is invoked.
- **D)** Force `tool_choice` to name one specific tool from the pair for every turn, so the model never again has to decide between the two options.

## Q4
In the multi-agent research pipeline (Scenario 3), the synthesis subagent's only job is to combine findings that other subagents have already produced. Its tool set still includes `web_search` and `scrape_website`, inherited from a shared subagent template, and logs show it invokes one of these two tools in 30% of synthesis runs instead of synthesizing the findings it was already given. What is the most likely root cause, and what is the correct fix?

- **A)** Remove `web_search` and `scrape_website` from the synthesis agent's tool set; give it only synthesis-relevant tools, plus one cross-role tool if truly needed.
- **B)** The model defaults to search because `tool_choice` is set to `"auto"`; switching to `"any"` will force it to use only tools meant for synthesis.
- **C)** Add a much stronger, more explicit system-prompt instruction forbidding use of `web_search` and `scrape_website` in this specific role, while still leaving both tools fully available to the agent for edge cases.
- **D)** Merge the synthesis subagent with the search subagent into one agent so tool ownership no longer needs to be enforced.

## Q5
In a developer-productivity CI pipeline (Scenario 4), a single agent has three tools available at every step — `run_tests`, `run_linter`, and `deploy_preview` — and the team must guarantee that `deploy_preview` is never called until both `run_tests` and `run_linter` have already succeeded earlier in that same run, while keeping normal, flexible tool selection for every other step of the pipeline. Which approach best guarantees this ordering without over-constraining the rest of the pipeline?

- **A)** Force `tool_choice` to name `deploy_preview` on every single turn of the run so the model is continually reminded that shipping is the pipeline's ultimate end goal regardless of test status.
- **B)** Set `tool_choice` to `"any"` for the entire run; because some tool must be called on every turn regardless of type, the correct dependency order will naturally emerge over time.
- **C)** Force `tool_choice` to `run_tests` then `run_linter` on the run's first two turns, keep `deploy_preview` out of the tool set until both succeed, then return `tool_choice` to `"auto"`.
- **D)** Write the required run_tests-then-run_linter-then-deploy_preview order into the system prompt and leave `tool_choice` at its default `"auto"` setting with all three tools available the whole time.

## Q6
A customer-support resolution agent (Scenario 1) whose role is to resolve billing disputes currently carries an 11-tool bundle inherited from a shared "general support" template, spanning billing, shipping, account-deletion, and internal HR lookups. Selection telemetry shows that in 3% of billing-only turns the agent calls `delete_account` or `hr_lookup` instead of the correct billing tool, and the team must decide how aggressively to prune the tool set. Which pruning strategy is the most defensible, balancing reliability against operational flexibility?

- **A)** Remove every tool except the single most-used billing tool and force `tool_choice` to that one tool for the entire session.
- **B)** Keep all 11 tools fully available to the agent, but add a runtime hook that specifically blocks calls to `delete_account` and `hr_lookup` only for this particular agent's sessions.
- **C)** Fine-tune a small classifier that decides, per request, whether to expose the full 11-tool bundle or only the billing tools.
- **D)** Scope the agent to the billing-resolution tools it needs, plus one or two high-frequency cross-role tools — not the full 11-tool bundle.
